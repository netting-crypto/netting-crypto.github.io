真实问题

大多数 AI 对话把探索过程和最终知识混在同一条消息流里。用户得到很多回答，却很难决定什么值得留下、这些内容如何组织，以及下一次提问应该带上哪些上下文。

关键产品判断

Conversation 不等于知识

对话负责探索，Canvas 负责承载用户主动保留和组织的内容。AI 说过什么，不自动成为用户的知识。

Context 属于每一次提问

Card、文件、文件夹、图片和引用按 Question 选择，而不是永久绑定到整段 Conversation。

使用上下文不等于建立关系

Add Context 只服务当轮推理；Card 与 Conversation 的持久 Link 必须由用户显式建立。

统一 Conversation，切换 Runtime

取消 Chat、Agent、Executor 的模式切换，让 Codex、OpenCode、ZCode 成为同一交互模型下的执行能力。

系统如何工作

提出问题
选择当轮 Context
Agent 回答或执行
Add to Canvas
Fork 新分支
建立显式 Link
